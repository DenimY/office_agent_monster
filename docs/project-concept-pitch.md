## 1. One-liner & Elevator Pitch

### One-liner (한 문장)

**office_agent_monster**는 오피스 맵 위를 돌아다니는 픽셀 몬스터 AI 에이전트 팀이다. 몬스터를 클릭하면 역할과 현재 작업이 보이고, Team Lead가 리스크를 걸러 인간(창업자)에게만 중요한 일을 올린다.

### 30초 피치

우리는 AI 에이전트를 “로그와 대시보드의 점”이 아니라 **오피스에 사는 몬스터 팀**으로 만듭니다. 개발자·디자이너·팀 리드가 맵을 돌아다니며 일하고, 클릭하면 역할과 지금 하는 일이 보입니다. Team Lead는 문제를 일찍 잡고, 이슈를 정리한 뒤 **중요한 것만** 창업자에게 올립니다. Claude·Cursor·GPT·Gemini 등 여러 모델을 역할·작업에 맞게 묶습니다. v1 아트는 공룡·유령 스타일 픽셀로 충분합니다.

### 2분 피치

멀티 에이전트는 이미 ChatDev·MetaGPT·CrewAI처럼 “가상 회사”로 움직입니다. 다만 대부분 UI는 채팅·그래프·트레이스라서, 사람이 “지금 누가 뭘 하고 막혔는지”를 한눈에 보기 어렵습니다. ClawProwl·Agent Town·DeskRPG 같은 공간형 오피스가 뜨고 있지만, 대개 사람 직원 메타포이고 계층적 감독 UX는 약합니다.

office_agent_monster의 핵심은 세 가지입니다.

1. **몬스터 캐스트 + 클릭 인스펙트** — 종/스킨으로 역할군을 구분하고, 클릭 한 번으로 역할·현재 작업·상태를 본다.
2. **Team Lead 에스컬레이션** — Lead가 리스크를 조기 감지·분류하고, 인간에게는 요약된 중요 이슈만 전달한다.
3. **멀티 모델 오케스트레이션** — Claude / Cursor / GPT / Gemini를 역할·작업·비용·지연에 따라 라우팅한다.

제품 언어는 **한국어·영어(i18n)를 처음부터** 지원한다. 전달면은 **웹 앱(브라우저)** — Mac·Windows 모두 동일 URL로. 포지셔닝: *에이전트 팀을 위한 Sims / monster ranch — 바닥에서 역할과 실시간 작업을 보고, Team Lead가 스웜을 최적화하는 모습을 본다.*

## 2. Problem — 왜 Spatial Multi-agent + Supervision인가

| 고통 | 현실 | 우리가 겨냥하는 해결 |
| --- | --- | --- |
| **인지 과부하** | 에이전트가 늘수록 로그·트레이스·슬랙 알림이 폭발한다 | 오피스 맵이 “누가 어디/무슨 상태인지”의 1차 시야 |
| **감독 부재** | 자율 에이전트는 조용히 실패하거나 비용을 태운다 | Team Lead가 순찰·분류·재배정·에스컬레이션 |
| **역할 비가시성** | “개발자/디자이너/리드”가 코드에만 있고 UI에 없다 | 몬스터 종·클릭 카드로 역할·작업을 즉시 노출 |
| **모델 파편화** | Claude·GPT·Gemini·Cursor를 제각각 쓴다 | 역할/작업 기준 라우팅 + 비용·지연 가시화 |
| **인간 개입 타이밍** | 모든 알림을 받거나, 너무 늦게 알게 된다 | Lead가 노이즈를 걸러 **중요 이슈만** 창업자에게 |

**왜 공간(spatial)인가:** Generative Agents / AI Town이 보여준 대로, 맵 위 캐릭터는 “계획·이동·상호작용”을 직관적으로 읽게 한다. 소프트웨어 팀 작업 관찰에 같은 메타포를 쓰면, 옵저버빌리티 대시보드보다 창업자·비엔지니어에게도 설명하기 쉽다.

**왜 감독(supervision)인가:** ChatDev·MetaGPT·CrewAI의 계층/SOP는 코드 쪽에 이미 있다. 제품 빈틈은 **그 계층이 맵 위에서 드라마처럼 보이는 것** — Lead가 막힌 몬스터에게 다가가고, 이슈를 묶고, 인간에게만 올리는 UX다.

## 3. Product Vision — 오피스 맵, 픽셀 몬스터, 클릭 인스펙트

### 화면 한 장으로 설명

- **풀블리드 오피스 맵** — 책상, 회의 존, 화이트보드, 휴게 공간. 에이전트(몬스터)가 돌아다니며 작업한다.
- **픽셀 몬스터 캐스트** — v1은 **공룡(dino) / 유령(ghost)** 스타일. 캐릭터 아트 퀄리티는 v1 성공 조건이 **아님**. 종/색/악세서리로 역할군을 구분하면 충분.
- **클릭 → 인스펙트 카드** — 역할, 현재 작업, 상태(대기/작업중/막힘/에러), 사용 모델, 최근 Lead 개입. 이게 **히어로 인터랙션**.
- **Team Lead 가시성** — Lead 몬스터의 순찰·리뷰·재배정이 맵에서 읽힌다. 인간에게 올라간 이슈는 별도 “에스컬레이션” 피드.
- **i18n (필수)** — UI·인스펙트 카드·에스컬레이션 메시지·온보딩을 **한국어 / 영어**로 day-one 지원. 문자열 하드코딩 금지, locale 전환 가능.
- **전달면 (web-first)** — v0/v1은 브라우저 웹 앱. 타깃 OS는 **Mac + Windows** (설치 패키지가 아니라 웹으로). 데스크톱 셸은 나중.

### 브랜드/비주얼 원칙 (짧게)

- 첫 뷰포트 = 브랜드(몬스터 오피스) + 한 줄 헤드라인 + 짧은 설명 + CTA + 맵/몬스터 비주얼.
- 옵스 대시보드(카드 그리드·스탯 스트립·보라 그라데이션)처럼 보이지 않게.
- 몬스터 판타지가 빠지면 ClawProwl/Agent Town 스킨으로 읽힌다 — **첫 화면에서 몬스터가 주인공**.

## 4. Core Loop — 할당 → 배회/작업 → Lead 감시 → 인간 에스컬레이션

```
[인간/시스템] 작업 할당
        ↓
[몬스터 에이전트] 맵을 돌아다니며 작업 (말풍선/상태)
        ↓
[Team Lead] 리스크·블로커·비용 이상 감지 → 분류·재배정·최적화
        ↓
중요도 높음? ──아니오──→ 팀 내부에서 해결 (인간은 맵만 봐도 됨)
        ↓ 예
[인간 창업자] 요약된 에스컬레이션만 수신 → 결정/승인/무시
        ↓
결과 반영 → 다음 할당
```

| 단계 | 사용자가 보는 것 | 시스템 하는 일 |
| --- | --- | --- |
| Assign | 작업이 몬스터에게 붙음 | 역할·스킬·가용성으로 라우팅 |
| Roam / Work | 이동, 책상 착석, 말풍선 | 모델 호출, 툴 사용, 상태 갱신 |
| Lead monitor | Lead가 다가가거나 하이라이트 | 이상 탐지, 이슈 묶기, 재시도/재배정 |
| Escalate | 에스컬레이션 카드 (KR/EN) | 중요도·근거·추천 액션만 전달 |
| Decide | 승인 / 방향 수정 / dismiss | 정책·다음 작업에 반영 |

루프의 약속: **인간은 상시 감독자가 아니라, Lead가 고른 결정 포인트에만 등장한다.**

## 5. Role Model — Team Lead / Developer / Designer (+ 계층)

### 역할 (v1 최소 세트)

| 역할 | 몬스터 힌트 (예시) | 하는 일 | 보고 대상 |
| --- | --- | --- | --- |
| **Team Lead** | 큰 공룡 / 뚜렷한 리드 마크 | 리스크 조기 감지, 이슈 정리·우선순위, 재배정, **중요 부분만 인간에게 에스컬레이션**, 팀 최적화(중복·비용·블로커) | 인간(창업자) |
| **Developer** | 공룡 워커 | 구현, 디버그, 코드/툴 실행, PR·패치 초안 | Team Lead |
| **Designer** | 유령 워커 등 | UI/카피/비주얼 초안, 디자인 제약 검토 | Team Lead |

v1 이후 확장 후보: QA, Researcher, Ops — 다만 초기에 역할을 늘리기보다 **Lead ↔ Worker ↔ Human** 삼각형을 단단히.

### 계층이 작동하는 방식

1. **할당 권한:** 인간은 목표/에픽을 주고, Lead가 워커에게 쪼개 배정(인간은 직접 할당도 가능).
2. **상태 소유:** 워커는 자신의 현재 작업을 인스펙트 카드에 노출; Lead는 팀 보드(막힘, 비용, SLA)를 본다.
3. **개입 규칙:** 워커 실패·반복 루프·예산 초과·상호 충돌 → Lead 1차 대응 → 정책상 “인간 필요”만 에스컬레이션.
4. **최적화:** Lead는 “누가 thrashing인지”, “중복 작업”, “더 싼/빠른 모델로 충분한 작업”을 재라우팅.

Team Lead의 제품 정의 (한 줄): **문제 위험을 일찍 찾고, 이슈를 정리하며, 중요한 것만 창업자에게 올린다.**

## 6. Model Orchestration — Claude / Cursor / GPT / Gemini

과설계 없이, v1에서 말할 수 있는 수준으로 구체화.

### 원칙

- **역할·작업 타입으로 1차 라우팅**, 비용·지연으로 2차 조정.
- **한 에이전트 = 한 primary 모델**을 기본으로 하되, Lead/시스템이 재라우팅 가능.
- **Cursor**는 “IDE/리포 작업 실행면”, 순수 LLM 채팅면과 분리해 스토리텔링.
- 모든 호출은 인스펙트 카드에 `model`, `tokens/cost(대략)`, `latency`를 남긴다 (옵저버빌리티 패턴은 Langfuse/AgentOps에서 차용).

### 역할별 기본 매핑 (초안 — 교체 가능)

| 역할 / 작업 | 기본 모델 후보 | 이유 |
| --- | --- | --- |
| Team Lead — 분류·요약·에스컬레이션 문구 | **Claude** 또는 **GPT** (강 추론/요약) | 판단·우선순위·인간용 문장 품질 |
| Developer — 설계/난이도 높은 코드 | **Claude** / **GPT** | 깊은 추론 |
| Developer — 리포 편집·패치·PR | **Cursor** (에이전트/IDE 경로) | 실제 코드베이스 작업 |
| Designer — 카피·레이아웃 제안 | **GPT** / **Gemini** | 빠른 초안·멀티모달 여지 |
| 대량/저위험 분류·번역·상태 문구 | **Gemini** 또는 경량 티어 | 비용·지연 |
| i18n 문자열/에스컬레이션 이중 언어 | 번역 전용 경로 또는 동일 모델 + locale 프롬프트 | KR/EN 일관성 |

### 누가 누구를 감독하는가

```
Human (창업자)
  └── Team Lead agent  (감독·에스컬레이션 게이트)
        ├── Developer agents  (Cursor/Claude/GPT …)
        └── Designer agents   (GPT/Gemini …)
```

- **모델 간 상호 감독이 아니라, 역할 계층이 감독한다.** 모델은 역할의 “두뇌 공급자”.
- Lead는 워커 출력의 품질·리스크를 보고 재시도·모델 교체·인간 에스컬레이션을 결정.
- 비용 가드: 워커 예산 초과 시 Lead가 경량 모델로 내리거나 작업을 쪼갬.

### 아키텍처 스토리 (외부 설명용 한 단락)

“우리는 단일 LLM 제품이 아니라 **멀티 모델 런타임 위의 게임형 셸**입니다. 오피스 맵과 몬스터는 UX이고, 뒤에서는 작업 타입에 따라 Claude·Cursor·GPT·Gemini가 붙습니다. Team Lead 에이전트가 그 스웜의 감독관이자, 창업자로 가는 알림의 필터입니다.”

## 8. Differentiation Wedge

경쟁이 “AI 직원이 있는 오피스”를 이미 차지한다. 우리가 이겨야 할 쐐기는 세 겹이다.

1. **Monster cast** — 사람 직원 스킨이 아닌, 공룡·유령 등 몬스터 아이덴티티. 종 = 역할군 힌트. 기억에 남고 브랜드가 된다.
2. **Click-inspect as hero UX** — 트레이스 탐험이 아니라, 클릭 한 번에 역할 + **현재 작업**. 
3. **Team Lead → Human escalation** — 계층이 코드에만 있지 않고, Lead가 노이즈를 흡수하고 창업자에게만 중요 이슈를 올린다.

부가 쐐기: **프레임워크 비종속 게임 셸**(특정 Gateway/Hermes/OpenClaw 락인 완화) + **KR/EN day-one i18n**.

리스크: 몬스터·계층·현재작업이 첫 화면에서 안 보이면 “또 하나의 오피스 스킨”으로 읽힌다.

- **코드 홈 (의도):** 로컬 `/Users/youkyungmu/Documents/Project/git/office_agent_monster` — Store 문서는 동기화 전 interim.

### v0 — “한 방 데모” (설득용)

- 브라우저에서 열리는 정적 또는 반자동 오피스 맵 + 몬스터 3~5마리 배회.
- 클릭 → 역할 + 현재 작업 카드 (가짜/스크립트 데이터 가능).
- Team Lead가 블로커를 “감지”하고 인간에게 에스컬레이션 카드 1~2장 (데모 시나리오).
- 모델 배지는 UI에 표시 (실제 멀티모델 호출은 stub 가능).
- KR/EN 토글.
- Chrome/Edge/Safari 등 주요 데스크톱 브라우저에서 Mac·Windows 스모크.

**성공 기준:** 창업자가 외부인에게 30초 만에 “아, 몬스터 팀이고 Lead가 나한테만 올린다”를 이해시킴 (링크 하나로).

### v1 — “진짜 루프”

- 웹 앱에서 실제 작업 할당 → 워커 실행(최소 1개 LLM + 가능하면 Cursor 경로 1개) → 상태 반영.
- Lead 규칙: 실패 N회 / 타임아웃 / 키워드 리스크 → 분류 → 에스컬레이션 또는 재배정.
- 모델 라우팅 테이블(설정 가능) + 대략 비용 표시.
- 인스펙트: 역할, 현재 작업, 모델, 최근 이벤트.
- i18n 완성도: locale 파일, 에이전트 출력 locale 정책.
- 프레임워크 어댑터 1개(직접 런타임 또는 기존 OSS 중 하나) — **락인 최소화 설계**.
- Mac·Windows 데스크톱 브라우저 지원을 QA 기준에 포함 (네이티브 설치 아님).

**비범위 (v1에서 하지 않음):** Electron/Tauri 설치형, 고퀄 일러스트, 다수 역할, 멀티플레이어, 풀 3D, 모든 모델 동시 프로덕션 최적화, 복잡한 SOP 빌더.

**데스크톱을 다시 검토할 때:** 로컬 리포/파일 감시, OS 백그라운드 상주, 오프라인 필수, 또는 브라우저로는 불가능한 Cursor/IDE 딥링크 제약이 제품 필수일 때.
